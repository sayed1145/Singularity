# 奇点 · Singularity 8.4-beta

基于本次提供的 **8.3-beta 完整源码包**升级，面向 **Mindustry v160.5**。
同一个 JAR 包含桌面 Java 类与 Android DEX；模组内部名称仍为 `blackhole`，用于替换旧版本，而不是并装。

## GitHub 分发方式

- 仓库和 GitHub 自动生成的源码 ZIP **只包含源码、必要资源、构建/测试脚本及报告，不包含 JAR、DEX 或编译类**。
- 通用 JAR 作为 [8.4-beta Release 的独立二进制附件](https://github.com/sayed1145/Singularity/releases/tag/8.4-beta) 下载，不嵌入源码包。
- JAR 校验值见 Release 说明和 `docs/v84/release-audit.json`。直接使用源码包时，请另行下载 JAR 或自行构建。

### 两台新设备的建模

完成后的机身及建造规划预览全部由程序化三维几何实时绘制，**没有新增机身贴图，也没有远景贴图回退**。炉内转子随炉温旋转；分类器有低速待机旋转、输送加速和配置色标。

模型的占地、投影、转子与壳体间隙均有自动检查。菜单和施工阶段使用引擎通用垃圾桶/筛选标识，它们不是机身贴图。已有设备沿用 8.3 的资源与绘制方式，没有将所有老设备重做一遍。

打开 [离线模型动画预览](docs/v84/models.html)；它不依赖网络。预览来自实际 `draw()` 顶点录制后软件光栅化，**不是游戏实机截图或 FPS 测试**。

### 护盾规则

- 断电或禁用：不拦截弹丸，保留当前护盾；断电时暂停破盾重建。
- 按官方 `BulletType.shieldDamage` 计算损耗，不重复吸收已吸收的弹丸。
- 友军和不可吸收弹丸不会扣盾；接入原版坠毁爆炸护盾接口。
- 极光冷冻液仍为可选强化：扩大半径 8 格，恢复与重建速度 ×1.9；满额供电时重建约 7.38 秒。
- 共振碎片仍提供 22 秒、+5200 容量强化；强化到期后容量与当前值都会限制到基础上限。

## 安装与升级

1. **先备份游戏存档及战役数据。**
2. 删除/替换旧的 Singularity JAR，只保留 `Singularity-v8.4-beta.jar`。
3. 从 Mindustry 的“模组 → 导入模组”导入 JAR，重启游戏。ZIP 是源码与报告包，不是另一个需要并装的模组。

### 旧存档

- 已用原始 8.3 JAR 实际创建存档，再用 8.4 加载验证。
- 旧战术指挥核心按引擎缺失方块处理变为空地；**不保留占位方块，也不返还建材**。
- 8.3 未破盾的穹顶首次读取时恢复满盾，修复旧版空盾初始化问题；原本正在重建的计时保留。8.4 新存档会精确保留受损护盾值。
- 旧战役在引擎恢复 `SectorInfo` 后补上 Boss 规则。正在防守且进度已经很靠后的地图，会把终局安排到未来；重复加载不叠加 Boss，不重置资源和当前波次，也不重启已占领区域的波次。
- **不会重挖旧存档地形或拆玩家建筑。** 地形拓宽针对新生成地图。旧自然通路过窄时，优先换到安全入口；没有合适入口时，用相近名义生命预算的带额外护盾飞行 Boss，避免地面 Boss 被自然地形困住。

## 构建与复测

依赖 JDK 17、官方 Mindustry 160.5 桌面/服务器 JAR、R8、Android 平台 JAR；Python 3 用于测试驱动。依赖不放入交付包。

```bash
export VENDOR=/你的外部工具链目录
bash tools/setup_env.sh v160.5

# 沿用包内未变化的老模型资产；新设备完全实时，无须烘焙。
SKIP_BAKE=1 bash build.sh
# 输出 dist/Singularity-v8.4-beta.jar

bash test_server.sh --mode integration

# 可选：提供原始 8.3 JAR 或包含它的 ZIP，重做真实跨版本存档测试。
bash test_server.sh --mode migration --baseline /路径/Singularity-v8.3-beta.zip.txt
```

如果要重新烘焙所有旧模型，运行 `bash build.sh`；新设备会被烘焙器明确跳过。`tools/preview/src/preview/UtilityCheck.java` 是新设备绘制检查程序。

工具链、临时服务器、编译目录和旧发布日志不包含在源码 ZIP 内。当前测试驱动取代了旧版本带“恢复战术核心”假设的测试脚本。
